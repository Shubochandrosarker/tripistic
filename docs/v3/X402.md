# x402 — NOT IMPLEMENTED

## Status

The data model exists. **No route is protected, no facilitator is called, and no
payment can be made or verified.** `X402_ENABLED` is `false` in `.env.example`
and there is no code path that reads it.

This is recorded honestly rather than shipped half-built, because a payment rail
that looks present but does not verify is worse than an absent one.

## What exists

`x402_payments` and `x402_access_grants`, with the constraints the eventual
implementation needs:

- `transaction_reference` is **unique** — the same settlement can never be
  credited twice. That constraint is the replay defence, not a convention.
- `request_id` is unique, for idempotent retries.
- `token_hash` is unique and the token itself is never stored, so a leaked
  grants table is not a set of working credentials.
- `workspace_id` is nullable, because an unaffiliated agent is a legitimate
  caller.

Both tables are entirely separate from `Payment`. Conflating them would put an
experimental settlement rail in the path of the revenue that pays the bills.

## Architecture when it is built

Protect only explicitly configured routes:

```
/api/agent/travel-search
/api/agent/itinerary
/api/agent/availability
/api/partner/premium/*
```

Never `/login`, `/dashboard`, `/admin`, or traveler booking checkout. Stripe
remains the only traveler payment path.

Required before enabling: testnet-first configuration, an explicit
production-network guard so a testnet transaction can never be accepted as a
production payment, facilitator verification of every proof before access is
granted, and replay tests.

## Why it was deferred

Every other V3 phase either completes something already load-bearing or is
gated behind an entitlement that can stay off. x402 is a new external
dependency on a settlement network with real money semantics, and shipping it
without the testnet/production guard tested end to end would be the one change
in this release that could lose money rather than just fail.

The `x402_api` plan flag was **removed** from the catalogue rather than left
defined-but-unenforced, so the entitlement-coverage guard stays meaningful.
